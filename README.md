# MapReset 2.3.0 · Paper 1.16.5

[下载 2.3.0 JAR](https://github.com/lin-rog/MapReset/releases/tag/v2.3.0) · [Paper 服务端测试报告](请先阅读-测试报告.md)

从源码构建使用 JDK 8–21 和 Maven，运行 `mvn clean verify`。JAR 位于 `target/`。


面向 Paper 1.16.5 的在线地图重置插件。字节码 Java 8；世界异步生成依赖 Paper 1.16.5，不能用普通 Spigot 替代。正式建筑尚未提供，默认生成随机尺寸占位结构。插件不会主动关闭或重启服务器。

## 2.3 道路横截面与真实服务端测试

- 道路入口和中段一起圆滑处理，避免只有中段弯曲、入口突然折转。地形寻路禁止沿起终点方向倒退，防止在建筑前绕成回头弯；真实 Paper 地形数据已加入回归测试。
- 按沿路距离构造连续高程，再投影到整条路面，避免多个路面片段重叠时由先写入的方块决定高度。
- 本版稳定使用 5 格名义路宽（范围要求的上限），减少按单点粗糙度反复改变宽度造成的鼓包；方块网格的斜线边缘仍会有自然锯齿。
- 默认缓坡约每 3 格水平距离上升 1 格；入口高差较大时适度加陡，超过允许坡度则重新选址。前后入口保持平坦。
- 用半格台阶衔接斜向坡面，在较高的整格行放置朝向上坡的楼梯。台阶材质取配置楼梯对应的 `_SLAB` 类型，避免斜向道路出现整格高坎；平路仍使用 road-a / road-b 混合材料。
- 路肩按最近的道路断面计算，只修整实际有高差的地形；不再把重叠采样的最低高度累积套用到同一列。较深切坡扩大过渡范围，建筑周边修整不覆盖更靠近道路的断面。
- `mapreset-coordinates.yml` 的道路 blocks 文本新增第六列 `slab`，前五列保持兼容；`y` 仍表示所放路面方块的 Y，台阶可站立顶面是 y+0.5，整块是 y+1，楼梯按朝向有两个高度。

下面的 2.2 水面、护栏和树木清理修复继续保留。[真实 Paper 测试记录和实际方块重建图](请先阅读-测试报告.md)随仓库提供；重建图不是游戏客户端截图。

## 2.2 已有修复说明

- 水面高度与水底地形分开记录。建筑第一层按占地和入口附近最高水面抬高，基础允许向水下支撑，主体不会按海底平均高度下沉。
- 平坦水域使用单段缓弯路线；需要避山时使用带方向/转弯代价的 A*，取消强制中间折点。路面高度受水面下限约束；水下肩部不再大面积填平成陆地。
- 原始水域 5 格范围内的路段，两侧设置高出路面 2 格的玻璃护栏，玻璃不占铺路单元，建筑入口留空；不生成玻璃顶。护栏柱坐标记录在 `water-rails.columns`。
- 修整前扫描受影响列，沿相连树干和树冠清除受影响树木，分 tick 执行；扫描范围包括路面、路肩、建筑和护栏。此处理用于新备用图生成，不追溯修复现有地图。
- 自查增加建筑/道路水面高度、道路 3 格净空、护栏材质和路面占用检查。失败的地图不会进入 READY 库。
- 升级会将旧生成版本的备用图移到 `reserves/retired` 后补库；已有当前游戏地图保持原样，下一次 reset 使用新版生成图。保留原配置、模型、永久大厅和维度模板。

## 安装与第一次初始化

1. 备份服务器。将 mapreset-2.3.0.jar 放入 plugins，移除旧版 JAR，完整启动。
2. 全体玩家下线，在控制台执行 `mapreset setup`。它备份 server.properties / bukkit.yml，设置永久虚空大厅为默认世界，记录原三界名字，并复制 playerdata / stats / advancements；存在不同内容时拒绝覆盖。
3. 手动完整重启一次，使大厅成为默认世界。Paper 默认世界不能在线卸载，这是一次性安装步骤；日常 reset 不需要重启。status 应显示“大厅默认=true”。
4. 等待固定地狱、末地模板及 5 张备用主世界完成。1936 个区块/张，原版生成、扫描、规划、修整分阶段执行，耗时取决于硬件。
5. 执行 `mapreset reset`。所有玩家撤到大厅、三界在线切换、自查成功后解锁，玩家仍留在大厅。维护者可以 `mapreset play` 进入；游戏插件可在解锁后自行传送普通玩家。

不要用 /reload 或 PlugMan 热重载。已有 v2 配置不会被默认值覆盖；升级时核对材料配置、结构格式以及 placeholders 配置。旧建筑版本备用图会移入 retired，重新补库。

大厅不存在时以 NORMAL 环境全空气生成器创建，不放置平台。大厅中提供飞行、无重力、伤害保护，离开后恢复原状态。默认世界必须为大厅。现有同名大厅会保留，创建过的区块不会自动清空。

## 指令与权限

所有指令均要求 OP 且拥有 mapreset.admin（默认 OP），控制台可执行；setup 需要无人在线。

| 指令 | 功能 |
|---|---|
| mapreset status | 查看任务、隔离、备用数 /5、大厅默认状态 |
| mapreset setup | 一次性准备大厅默认世界配置 |
| mapreset reset | 重置三界；有生成/重置任务或隔离时拒绝重复执行 |
| mapreset generate | 手动启动一次补库；generation.enabled=true 时继续补满 5 张 |
| mapreset check | 检查三界更新 ID、环境、UUID、种子、目录和主世界元数据 |
| mapreset recover | 隔离下恢复未完成的地图切换事务 |
| mapreset rollback | 在事务提交前回到旧三界，提交清理后不可回滚 |
| mapreset reloadstructures | 无任务时重读模型，退休旧版备用图并补库 |
| mapreset model a | 原地替换 a 的占位/旧模型，支持 a..j |
| mapreset play | 当前 OP 玩家进入已解锁主世界 |

其他插件：`Bukkit.dispatchCommand(Bukkit.getConsoleSender(), "mapreset reset")`。
可用 Java API `isResetInProgress()` / `canEnter(World)` 检查隔离。

## 在线重置与文件语义

锁定三界 → 撤离所有玩家 → 后台复制备用三界并 SHA-256 校验 → 主线程卸载 → 后台目录切换 → 主线程加载 → 自查 → 删除旧三界并消耗选中的备用主世界 → 再次自查 → 解锁、补库。

主世界从已完成 READY 库随机抽取；只有通过最终提交才删除该备用源。地狱和末地始终复制固定模板，不删除模板。事务日志支持切换中断恢复；文件路径限制在服务器根目录内，拒绝符号链接越界。

登录在 Paper PlayerSpawnLocationEvent 阶段改到大厅，避免先加载旧退出区块。传送、传送门、重生等入口受隔离保护；临时生成世界也不允许进入。在线重置不踢人。若其他插件强制加载/占用世界而卸载失败，保持隔离并记录原因，不强删已加载地图。

`plugins/MapReset/last-reset-check.yml` 记录更新结果、源消耗和 refill-state（REQUESTED / RUNNING / COMPLETE），备用不足 5 时补库。生成失败会关闭 generation.enabled，修复后重新开启配置并完整重启，或手动 generate。

## 原版地形、建筑和道路

- 三个游戏维度全部使用原版生成器。仅后处理备用主世界已生成区块里的原生铁、金、钻石、绿宝石矿，替换为石头；煤、红石、青金石保留。不更改下界矿石、矿物块或模型自身材料。
- 主世界边界中心 0,0，宽 700；完整方块坐标 -350..349。预生成 44×44 区块覆盖边界及边缘区块。1.16.5 原版洞穴保持原样，不引入 1.18 大洞穴系统。
- a 圆心半径25；b 半径180..250，c 在 x/z 取反位置独立计算地表高度；d 半径100..150，e 镜像，整栋占地距实际道路至少30格。
- f/g/h/i 分别在 (±320,±320) 半径15内选中心，整栋不越界。
- j 先在四个 (±325,0)/(0,±325) 锚点中等概率选一个，再在该锚点半径10的合法整数点中最大化 min(到b距离,到c距离)。j 也保留建筑接口。
- 扫描占地及周围24格范围，按高度方差/高差/水域评分，优先选择相对平缓位置；各建筑占地可用表面（陆地/水面）平均值确定楼层，并保证高于占地和入口旁水面。先保存预留元数据，再修整地形、修路，最后放置建筑。
- 固定石砖地基，第一层地板为第5格，默认 local y=4；地基下继续填至实际地面。仅建筑占地填基，不填整块区块。建筑周围24格平缓过渡，避免紧贴高墙。
- a-b、a-c 独立地形路径、平滑曲线；山地增加代价，绕行超过2倍时走山口并修整两侧缓坡。路面由配置两种方块混合，本版稳定采用5格名义宽度，强制连续3格核心；坡度每步最多1格，高差处使用两种配置楼梯。道路与入口第一层同高。

这些地形算法保证几何与连接约束；自然观感仍需在真实地图中查看并根据建筑模型调整。

## 模型接口和原地替换

默认 `placeholders.enabled=true`，每张图为 a..j 生成随机宽深9..19的石砖基础、发光角柱。正式模型保存于 `plugins/MapReset/structures/a.yml` 等文件；首次自动创建的是格式示例，不是正式美术建筑。

```yaml
width: 13
depth: 13
height: 11
foundation-layers: 5
first-floor-y: 4
# 入口可省略，默认四边中央；若声明则侧面必须匹配边界且 y=first-floor-y
entrances:
  north: {x: 6, y: 4, z: 0}
blocks:
  - '0,0,0,minecraft:stone_bricks'
  # 每个本地 x,y,z 唯一；可用完整 block-data，例如楼梯朝向
```

实际文件必须包含入口实心地板并预留3格净空，不能仅用上面的单块样例作为完整模型。
`StructureProvider` / `StructureSpec` 是 Java 接口；可通过插件 `setStructureProvider(...)` 接入外部模型系统。Y 表示地板方块层，玩家脚站在 Y+1；模型原点 Y=地板Y-first-floor-y。

生成图内：`mapreset-reservations.yml` 是修路前预留；`mapreset-coordinates.yml` 是最终尺寸、中心、楼层、原点、入口、道路单元、j 坐标。最终入口 `.y` 为地板层，`.first-floor-top-y` 为可站立高度。

修改模型文件后 `mapreset model b`：先核对新尺寸不越界、不挤占其他建筑、D/E不靠近道路；撤离玩家并卸载保存主世界，在 model-backups 下复制完整备份后再加载分批替换。中心、第一层和原逻辑道路入口不移动，新增3格连接段对接新门。新旧占地区别会清理和回填；连接段可能切开模型入口，请提供合理门洞。模型缩放不是无限的，不满足几何约束会拒绝。若替换中发生错误，保持大厅隔离；`recover` 只恢复地图事务，不会自动恢复模型备份，模型备份需管理员完整停服后手动还原。

关闭占位模式并 reloadstructures 后，新生成图直接使用正式模型。旧图替换与新备用图生成是独立操作。
